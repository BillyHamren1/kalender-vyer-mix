# Accepted personnel review descendant (dormant draft)

This is an owner-only draft SQL entry point in `scripts/internal-projects/accepted-personnel-review.sql`, not a migration, public RPC, enrollment, transport activation or release. It wraps the existing canonical project-review publisher and reuses `personnel_accepted_issuances_v1`; it introduces no ledger and computes no prices.

A review publication requires a current authenticated reviewer with current project authority. It holds row SHARE locks in stable order on the current auth user, profiles, user roles and selected project before authorization, fencing membership, tenant and deletion changes throughout later waits. Revocation either commits before authorization and is rejected, or waits until this authorized publication transaction commits; this is transaction ordering, not instantaneous invalidation of an already-authorized transaction. It serializes explicit grant changes with the grant command's advisory lock, then rechecks authority before checking idempotency. It locks current issuer enrollment, immutable stream enrollment, source binding and destination before canonical stream publication. Its ancestor must carry an immutable accepted issuance for the same issuer and epoch, be strictly above the enrollment floor, and match source organization, stream, worker and destination. Thus an old canonical shadow row cannot become accepted merely by review.

The command fingerprint binds actual `auth.uid()`, organization, issuer, epoch, stream, project, expected source revision, review sequence and idempotency key. Duplicate canonical publication requires an already-existing accepted marker with that fingerprint. No marker is minted for a duplicate that lacks it. Disabled enrollment, revoked grant, changed source binding and destination are checked even on exact retry.

Fresh publication and accepted marker are one transaction. The underlying canonical publisher derives project statuses from issued review events and checks frozen accepted rates; this wrapper repeats those proof checks before issuing the existing `operations-personnel-accepted-envelope.v1` full-stream envelope. The envelope retains canonical snapshot bytes/hash and has an explicit 524288-byte maximum. The only expected economics change is review status; money, rate, source allocation, coverage and currency remain frozen.

## Verification

Run `node scripts/internal-projects/accepted-personnel-review.test.mjs`. The harness composes the existing actual accepted-rate/review/source-issuer fixtures using the issuer's optional `afterIssuer` callback, and preserves their assertions. It uses PGlite with pgcrypto by default, or the existing `INTERNAL_PROJECTS_TEST_DSN` native database adapter. All identities, grants and economics are synthetic isolated fixtures.

Required proof covers anonymous/authenticated/service-role execute denial, floor and foreign-epoch rejection, unrelated project grant denial, current actor replay identity, revoked reviewer and issuer replay rejection, source-binding/destination changes, stale review/head, preliminary → confirmed → rejected → reopened lifecycle with exact frozen economics, marker-write fault rollback, and canonical shadow retry/descendant rejection.

Local composed PGlite run: **49 checks PASS**; both harness files pass `node --check`. Independent review reruns this same composed suite before publication. Native CI is still required. The dedicated `operations-accepted-review.yml` workflow runs exact PR head, PGlite and native PostgreSQL 17 in its own fresh service database; it never drops or resets shared test state. The native-only overlap fixture uses separate connections and `pg_blocking_pids` to prove both orderings: revocation-first makes the command wait then reject with no head/marker change; command-first holds issuer artificially, makes membership revocation wait until publication commit, then rejects retry after committed revocation.

Native overlap cases exercise user-role deletion; auth-user, profile and project row fences are structurally reviewed, not individually exercised by overlap tests.

No hosted role, concurrent grant-revocation, secure login or published UI acceptance is implied by these fixture tests. Native concurrency and hosted acceptance remain separate integration gates. This file is owned by the review-descendant task; the callback in `personnel-issuer-fixture.mjs` is owned and delivered by the Operations issuer/transport task.
