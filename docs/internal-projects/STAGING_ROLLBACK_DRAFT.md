## Rollback / safe suspension draft

Prefer suspension and forward repair. Before any later run, name the incident owner, snapshot method and reconciliation evidence. No destructive down migration is authorized here.

1. Stop initiating new browser review/Finance commands through capability flags; retain unresolved actor/body-bound requests. Keep narrowly authorized read/status access available for reconciliation when safe. Do not delete session records or issue new idempotency keys as recovery.
2. Disable accepted ingest and new dispatcher claims under the reviewed ownership/route controls. Allow a bounded in-flight interval or revoke current route/issuer as a deliberate suspension; failed finish must not claim delivered. Capture existing lease/outbox/receipt states. Preserve metadata/cost ordering evidence. Disabling ownership is fail-closed, not a transfer to legacy.
3. Retain permanent worker policy, floors, frozen mappings, accepted issuance markers, metadata receipts/tombstones, nonce/replay records and canonical outbox history. Keep SQL guards and same-OID legacy facades installed. Reverting the handler alone to an older shadow-only writer is unsafe for accepted-owned workers.
4. Reconcile exact immutable receipts and command keys. A lost ACK may have persisted at Finance; a lost financial response may already have posted. Reuse the original request/status under current authority; unavailable status is not noncommit. An operator must not manually stamp a receipt or outbox delivered.
5. Preserve financial command receipts, events, applied checkpoints and audit ownership. If money needs correction, use a separately approved canonical compensating command with a selected open accounting period and reason. Never delete events, rewrite old closed periods or restore an earlier database snapshot over subsequently posted money without an independently approved incident procedure.
6. Reverse optional frontend/Edge exposure only after data reconciliation. Keep necessary mode/status APIs and database safety guards. New role grants can be narrowed/withdrawn as a reviewed operation; do not grant private inner mutators to make an older client work.
7. Do not narrow TEXT Booking identity back to UUID: valid non-UUID identities may now exist. Preserve additive schema and use forward fixes. Do not lower floors, rebind immutable identities or resurrect tombstoned customer identity. A changed source identity requires a new explicitly reviewed prospective epoch/contract, not in-place rewrites.
8. Removing SQL objects, restoring generic writer bodies or dropping permit/ownership triggers is **not** a routine rollback. It requires proof that there are no accepted-owned rows, pending/committed commands or cross-app receipts depending on them, plus a separately reviewed migration. After first accepted evidence or money, default to retaining the guards and repairing forward.
