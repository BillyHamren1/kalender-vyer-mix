# Prospective accepted personnel source — design, not implementation

Reviewed source: Operations PR55 `0520f931bf596de5070fd7b28471f7ec4f78f37c`. Owner `/root/operations_recovery`, delegated root recovery lease. Parent approved a dedicated trusted Operations publisher attesting its own authenticated TLS read. Dormant source issuer implementation now exists; no key provisioning, enrollment, public mutation caller or dispatcher activation.

## Existing evidence and why v1 cannot be promoted

The canonical publication stores a complete `cost_snapshot`, raw Time snapshot, immutable source revision, and creation time. The same transaction writes `operations_personnel_cost_outbox` and project publication proofs. Both ingress and project-review paths validate issued rate/review provenance. Finance v1 transport and SQL finish both explicitly require `shadow_only=true`.

The service role can still directly insert publication/outbox/proof-shaped records. Outbox payload immutability prevents later alteration, but does not prove initial authenticity. A timestamp, correct monetary formula, accepted-looking schema, or hash supplied with its own body is not an accepted source. Current canonical service ingress trusts Time metadata supplied by its caller. Therefore adding an AFTER INSERT issuance trigger or merely using `created_at` would let old/generic service writers mint accepted evidence.

Current `readAuthenticatedTimePersonnel` signs the **request** with ES256; its response carries validated metadata/raw digest over TLS, not an independent Time-origin signature. A new Operations attestation must not claim that Time signed this response. Parent chose a separately trusted Operations publisher issuer explicitly attesting its own authenticated TLS read. The generic service role cannot mint that issuer proof. The mutating SQL issuer function remains private with no caller grants; the only exposed addition is a service-only read predicate returning an ancestry boolean. Public mutation adapter and accepted dispatcher remain absent.

## Smallest safe extension boundary

1. Retain the existing canonical streams, money snapshots, outbox identity and revision. Add default-empty **private issuance references**, containing no copied money, keyed to the exact new canonical publication/outbox. Preserve the existing shadow protocol and old rows unchanged.
2. Enroll an explicit source organization, destination organization, issuer/key and versioned enrollment epoch. At enrollment lock/read each stream head and establish the immutable exclusive revision floor. Never backfill accepted markers. Scope future stream eligibility explicitly; an absent stream is not automatically eligible. Source endpoint and issuer identity are pinned by enrollment, not caller input.
3. A designated default-off publisher performs the actual signed scoped Time read and existing source validation. It signs a dedicated short-lived source-attestation domain containing organization, actor or enrolled service identity, stream, raw Time digest, submission/version/state/decision sequence, expected Operations revision, nonce and enrollment epoch. The database verifies this proof with separately enrolled key material before canonical publication. A generic database service token alone cannot create the attestation or private marker. Keys are not created/exported during development.
4. Route that attested command through one private canonical publication transaction. Recheck current source/target enrollment and the accepted rate/review proofs; acquire the stream lock; create the next publication, outbox, project proofs and issuance marker atomically. Marker records server-assigned issue time, issuer/epoch and exact immutable source body fingerprint. An old retry without a marker must fail, never add one. A duplicate of a genuinely issued command returns the same receipt only after current command authority checks. No generic raw-table trigger confers authority.
5. Project-review publication must preserve the original accepted Time/source ancestry and use current authenticated project-review authority. Fresh approval cannot promote an unissued shadow ancestor. Its new snapshot/ref is issued atomically by the same private path after frozen-rate validation. Revoking a reviewer denies new review commands but does not rewrite already issued immutable evidence.
6. Produce the accepted envelope only from that reference joined to its exact canonical outbox and publication. Include source and destination org, issuer/enrollment epoch, outbox/publication identity, monotonic source revision, authoritative source-issued timestamp, unchanged complete cost snapshot/body digest and explicit `full_stream` membership. Missing-rate amount coverage is distinct from complete stream membership; do not conflate them.
7. Reuse the canonical outbox lease/retry machinery with a frozen explicit transport mode for prospective accepted rows. Old shadow claimant excludes accepted rows; accepted claimant excludes shadow rows and requires current issuer/enrollment/route. Do not create a parallel monetary or dispatch ledger and do not mutate delivered shadow rows into accepted ones. Scope ordered claiming per stream, token-bound ACK, lost-response replay and revocation recheck before sending.
8. Use a separately named request-signature domain and exact ACK schema for accepted evidence. Keep v1's strict `shadow_only=true` checks. The accepted ACK binds immutable envelope hash, outbox ID, issuer epoch, source/destination org, requested/applied/current revision and receipt ID. Verify authenticated ACK in both Edge and DB finish; accepted receipt means **received immutable source evidence**, not financial approval or automatic posting.

## Finance agreement

Finance's dormant wrapper expects immutable receipt identity, source org/stream/revision/fingerprint, authoritative `occurred_at`, explicit complete stream membership, and lines with project/line/status/coverage/amount/currency. Use source-issued time as the event occurrence timestamp; carry work date separately. Finance must choose its own explicit accounting period, not infer it from transport arrival.

Full membership authorizes identifying omitted previously bound lines for withdrawal. Rejected lines retain nonzero source audit amounts; their canonical lifecycle target is zero. Missing rate keeps coverage incomplete and must not be interpreted as zero cost. Finance never multiplies minutes/rates. Receipt creation and later actor-authorized application remain separate. Parent must settle exact shared field names and signature schema with Finance before code changes.

## Required tests before publication

- Preexisting exact-shaped shadow publications and duplicate keys never acquire issuance references; raw service INSERT and generic old RPCs cannot mint references.
- Disabled/unenrolled/wrong issuer or epoch/foreign tenant/at-or-below-floor fail before accepted effects. Two simultaneous enrollment/publication attempts cannot straddle the floor incorrectly.
- New attested canonical publication atomically creates one marker, outbox and snapshot; transaction fault creates none. Exact retry does not alter source timestamp or amounts.
- Altered raw Time/state/decision proof, rate/proof/body digest and cross-project review fail. Review of unissued shadow ancestry remains ineligible.
- Complete stream revision with omitted line withdraws once in Finance; missing-rate, rejected nonzero audit and mixed project cases preserve canonical economics.
- Default-off accepted transport emits no HTTP; shadow ACK in accepted domain and vice versa fail; invalid/expired signatures, nonce replay and mismatched ACK cannot finish lease.
- Two dispatch workers, lease expiry, lost response and current route/issuer revocation preserve ordered immutable delivery. Native PostgreSQL tests required in addition to PGlite.

Dormant draft SQL and source command preparation are implemented under this design, not installed as migrations. Receiver adapter, public issuer port, accepted dispatcher, project-review accepted descendants and feature activation remain absent. Accepted Finance source chain remains an open gate.

## Dormant implementation checkpoint

Implemented in `scripts/internal-projects/accepted-personnel-issuer.sql` as a **draft outside migration discovery**, plus the uncalled `project-personnel-source-issuer.ts` producer. Parent selected the dedicated trusted Operations issuer: it attests its authenticated TLS read; no claim of Time-origin response signature.

The producer accepts only scoped IDs, performs the existing authenticated Time read and calculation, then signs the exact command using the separate HMAC domain `operations-personnel-source-attestation.v1`. Current enrollment/source binding, destination, expiry, command digest and nonce are verified in private SQL. The canonical ingress and marker insertion share one transaction. Existing shadow duplicate keys cannot acquire markers. The signed command binds the full raw snapshot and all source decision evidence, issuer/epoch, source/destination and expected revision.

A same-Time-version state change may reuse frozen money only if the expected prior outbox already has an accepted marker under that same issuer/epoch. Both producer and SQL enforce it. A real newer Time snapshot can establish the first prospective marker using a fresh Operations calculation. A new review of old shadow money is rejected rather than repriced. Accepted envelopes retain the canonical source snapshot exactly, including rejected audit amounts and missing-rate coverage.

Validation: **45 PGlite checks PASS**, retaining all 33 prior rate/review assertions; **62 Vitest checks PASS across 3 files**, including five new actual producer cases (the existing fixture module also registers reused engine tests); transitive source-issuer TypeScript PASS. New tests cover disabled/no-network, authenticated source response errors, exact HMAC, stale/foreign/raw tamper, ancestry, missing enrollment/floor, secret/private-port ACL, issuer and destination revocation, nonce conflict, no old shadow promotion, immutable retry, and injected marker-fault rollback including nonce plus successful identical retry.

The existing isolated CI workflow now runs this strict superset on PGlite and PostgreSQL 17 separately. Native results on a newly published exact head remain pending until publication. All keys/enrollment rows exist only as disposable test fixtures.

Still deliberately absent: a callable issuer mutation port, hosted migration, real key provisioning and atomic enrollment operation, accepted-versus-shadow claim isolation, signed accepted dispatcher/ACK, project-review accepted descendants, Finance receiver wiring and real authenticated hosted acceptance. Private issuer invocation is owner-only in the disposable fixture. No deployable path can call it; do not grant a caller or enable this draft until those coupled gates are implemented and reviewed.
