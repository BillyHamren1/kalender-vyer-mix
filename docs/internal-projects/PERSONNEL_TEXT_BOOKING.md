# Opaque Booking identity in personnel cost (dormant compatibility draft)

Booking IDs and Operations `projects.booking_id` are TEXT. The previous personnel calculator, target binding relation, lower publication validator and ingress comparison incorrectly required UUID. This draft accepts the exact opaque identity in the cost chain without changing Booking, project billing, invoicing or commercial row ownership.

The transport eligibility bound is **1–256 UTF-8 bytes**, not an asserted Booking schema limit. NULL remains valid for booking-free internal projects. UUID strings remain valid. Unicode, BOM and leading/trailing whitespace are preserved exactly; no trimming, case conversion or normalization occurs. NUL cannot be represented by PostgreSQL TEXT and is rejected in the calculator.

Apply `scripts/internal-projects/personnel-text-booking.sql` only after existing canonical accepted-rate/review/issuer definitions and before prospective metadata-v2 overrides. It changes only the target binding booking column and two canonical function details: Booking field validation in `20261001220652_operations_personnel_cost_evidence.sql`, and removal of the Booking UUID cast in the **latest** `20261012165000_operations_personnel_review_issuance.sql` ingress. Existing privileges and all tenant, source, rate, issued-review, replay and full-stream guards remain. No migration/activation is included.

Run `node scripts/internal-projects/personnel-text-booking.test.mjs` with PGlite or the existing isolated native DSN. It preserves the accepted-rate/review/issuer oracle, then adds actual calculator → signed issuer → canonical SQL with customer/internal project/internal activity, genuine non-UUID opaque Booking identity, missing rate, wrong binding/tenant/rate denial, full-membership omission denial, voided status and a new immutable empty correction.
