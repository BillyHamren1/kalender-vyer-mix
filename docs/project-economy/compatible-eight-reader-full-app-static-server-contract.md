# Bounded full-App static server boundary

This NEW server exposes only an already-built exact Operations `dist` tree to the later isolated browser proof. It is a static-file transport boundary, not an App, browser, authentication, provider, database, economic or deployment acceptance. It does not compile source, install packages, call Supabase, manufacture a session, proxy a request or answer any API.

The server accepts one absolute, non-symlinked dist directory and one inherited receipt FD. It inventories the complete tree before binding: at most 4,096 entries, depth 16, 64 MiB total, 16 MiB per file, owner UID, no group/other writes, regular single-link files, no hidden entries, symlinks or special files, and only the fixed web MIME suffix set. `index.html` and an `assets` directory are mandatory. Every served file is opened through pinned directory FDs with `O_NOFOLLOW`, read completely under a fixed deadline, and revalidated against the inventory before any bytes are sent. Directory, file or root replacement/mutation refuses the request or terminates the server; alternate bytes are never deliberately served.

The process binds an IPv4 socket only to `127.0.0.1` with port `0`, so the operating system chooses an unused port. It never binds wildcard, IPv6 or a caller-selected port. After `listen`, it writes one bounded owner-only receipt to the already-created, held `0600` regular FD. The receipt contains the loopback host, actual port, fixed project route, PID/session IDs and pinned dist device/inode. That receipt is discovery evidence only. It grants no signalling or cleanup authority and must be matched by the root controller to the separately acquired frozen-b901 PID/start-time/session ownership record.

Only `GET` and `HEAD` over HTTP/1.1 are accepted. Host must equal the returned `127.0.0.1:<port>`. Each connection carries one request and is closed. Headers are capped at 16 KiB and 32 fields; request targets at 2 KiB; transfer encoding, Range requests, non-zero bodies, duplicate Host/Content-Length, invalid ASCII and folded fields are denied. The server deliberately has no partial-content semantics. It is single-request-at-a-time, has backlog 16, two-second connection reads, at most 768 accepted requests and a fixed 120-second whole lifetime. `SIGTERM`/`SIGINT` stop the foreground process without creating descendants, making it compatible with the outer owned-process cleanup. Deadline, resource or identity failure returns no success certificate.

The only SPA fallbacks are `/`, `/index.html` and `/project/55555555-5555-4555-8555-555555555555/economy`; the native browser proof must use the fixed project route. Unknown routes and all `/api`, `/auth`, `/rest`, `/rpc`, `/graphql`, `/functions`, `/supabase` and `/provider` paths return a fixed denial and never receive `index.html`. Dot segments, encoded traversal, backslashes, NULs, absolute-form URLs and directory requests cannot select a file. There is no directory listing. HTML is `no-store`; hashed Vite assets under `/assets` receive immutable one-year caching; other admitted public assets receive a one-hour cache. MIME values are fixed and `nosniff` is always present.

The root-owned native controller must create and hold the private receipt file before launch, start this server as a new session through the independently reviewed long-running b901-derived custody adapter, compare the receipt PID/PGID/SID to that adapter's stronger PID/start-time record, and retain failure state until exact process absence is proved. The current browser-network helper is pinned to port 55784 and is therefore not yet compatible with this random-port contract; a separately reviewed successor must consume the returned origin without allowing arbitrary origins. Neither this file nor its tests authorize that browser change.

Local support tests run the real loopback server against a tiny synthetic dist and verify the fixed SPA route, GET/HEAD behavior, MIME/cache headers, random-port receipt, graceful foreground shutdown, API/auth/provider/unknown/traversal denial, hostile Host/method/body/header refusal, inventory rejection and mutation-before-response refusal. These tests do not use the exact809f build, Chrome, the provider adapter, an authenticated actor or the native owned-process kernel. A real Linux CI run on the cold exact build, followed by the browser chain and independently verified cleanup, remains mandatory before this boundary is integrated-runtime-tested.
