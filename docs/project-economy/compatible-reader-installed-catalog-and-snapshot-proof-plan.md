Legacy Booking/project/join writers do not all take canonical organization/economic/source advisory barriers. The frozen coherent `scope_membership_v1` capture therefore remains `as_of_graph`; current receiver facts remain `saved_receiver_heads_only`. Root and existing member locks cannot protect nonexistent join/project rows. No proposal here changes those labels or infers complete source/budget/EAC coverage.

The next causal graph fixture should use an independent actual TEXT Booking and actual existing tenant-bound root/member joins. First preserve the exact current saved composition and capture. Hold a real public read open; let a genuine legacy join/member INSERT commit without its canonical barrier. Prove the commit and that no false serialization wait was claimed. A subsequent fresh public read must reject changed membership with the unchanged endpoint-specific business-stale/authorization priority. Only an explicit actual authenticated re-enrollment/recomposition may create a new matching proof. Keep original captured history immutable, preserve permanent member/source ownership and compare exact old/new graph fingerprints. This is as-of plus fresh-currentness detection, not phantom-lock authority.

No product fix is authorized by this hypothesis; the actual concurrent result and endpoint compatibility review must decide policy. Unsupported isolation/source-currentness stays visibly unresolved.
