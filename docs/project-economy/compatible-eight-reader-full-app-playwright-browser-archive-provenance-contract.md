# Playwright Chromium archive provenance — held-FD source boundary

Status: **source-only verifier; archive acquisition, import and native browser remain blocked**.

This additive boundary is for Playwright 1.55.0 Chromium revision 1187/version 140.0.7339.16 and exact archive suffix `builds/chromium/1187/chromium-linux.zip`. It accepts only a held regular archive FD owned by the current effective user, mode 0600, link count one, at most 512 MiB, plus a canonical external evidence object. Evidence must name one of the three already reviewed Playwright origins, HTTP 200, zero redirects, identity content encoding, exact byte count and a lowercase SHA-256. The source never opens a URL or pathname and never downloads, signals, extracts, installs, launches a browser or mutates an application tree.

Verification rehashes the full FD with positional reads under a finite deadline and checks its complete identity before and after. It then validates bounded, single-disk, non-Zip64 central-directory and local-header metadata. Entry names must be canonical UTF-8 or printable ASCII, relative, unique and free of traversal, backslashes and NULs. Encryption, symlinks, unsupported compression identifiers, duplicate names, excess declared entries/bytes, overlapping declared data ranges and malformed offsets are refused.

This is deliberately not full ZIP or entry-payload validation. Payload CRC32, DEFLATE stream validity and data descriptors are not parsed or authenticated by this boundary. The receipt therefore binds exact archive SHA/bytes, declared entry count/expanded total and central-directory SHA while reporting only `archive_hash_matches_evidence:true` and `bounded_header_directory_consistency_verified:true`; it explicitly reports `entry_payload_crc_verified:false`, `compression_streams_verified:false`, `data_descriptors_verified:false`, `transport_provenance_verified:false` and `imported:false`. A future importer must independently validate every payload, CRC, compression stream and descriptor while extracting into its held private destination.

This receipt establishes integrity of already acquired bytes only when an independently reviewed downloader supplies truthful transport evidence and an exact expected archive digest. Neither exists yet. The observed installed Playwright cache is still not archive provenance. A separate independently reviewed held-FD importer must create a fresh private destination, enforce entry modes and counts, reject links/special files, bind the extracted executable/tree receipt and prove cleanup. Until those gates, the CLI always exits 78 and no integration admission changes.
