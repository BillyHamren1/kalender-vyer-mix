# Exact full-App source acquisition boundary

This NEW boundary prepares the immutable source input for the Operations full-App test. It is not a product, database, authentication, browser, provider, build or deployment acceptance. The only production-mode success path uses `/usr/bin/git` to archive commit `809f64e0fd98322c53d9c4e9697df5b515303812`, whose tree is `3d96301591652f9d86ccbbdf8ff26efcb7180ce9`. The path list is the exact ordered set of 2,445 files in manifest `4c6005bb374fa13f89aafc52ce4a013feaa1673454dce76bd09aee77c95e6434`, totalling 20,984,073 source bytes. No caller chooses another commit, tree, prefix, output name, path or Git executable.

The root-owned workflow must check out the candidate programme source and the exact App source into separate directories. The App checkout must be at exact HEAD `809f64e...`, have exact tree `3d963...`, and have no tracked worktree changes both before and after acquisition. The archive command is fixed to `git --no-replace-objects --literal-pathspecs -c tar.umask=0022 archive --format=tar --prefix=compatible-app-809f/ --output=/proc/self/fd/N 809f64e... -- <2,445 literal paths>`. It runs from a pinned FD-backed working directory. Network fetch, checkout, object discovery, attributes from the worktree and caller-provided Git options are outside this helper.

Before dispatch, the helper opens an empty owner-only `0700` archive parent and creates `primary-source.tar` once with `O_EXCL|O_NOFOLLOW`, mode `0600`. That FD remains held and is the only archive output passed into the child. The exact path order has its own `371cdd68...` digest. Archive size is bounded to 32 MiB. Parent, source root, programme root, archive FD and path identities are rechecked after the command. Replacement, hardlinking, symlink use, extra archive-parent entries, wrong permissions, changed HEAD/tree, tracked changes, a non-empty stdout/stderr, timeout or uncertain cleanup suppress PASS. Failure retains the private evidence and never authorizes materialization.

Each Git process is created under the unchanged frozen owned-process kernel `b9011bfd...`. The wrapper verifies and executes those exact captured helper bytes. It preserves the helper's pre-exec PID/start-time/session acquisition, WNOWAIT leader pin, pidfd member signalling, live-group scan and irreversible reap boundary. This NEW adapter changes only the command purpose, FD set, FD-backed cwd, output limit and one shared 60-second acquisition deadline. It neither weakens nor edits the frozen helper. A distinct fresh owner-only journal contains bounded `0600` stdout, stderr, acquisition and closed records for all seven fixed commands. Any pending/uncertain child or missing closed record refuses success.

Acquisition PASS is followed, in the same isolated job, by the separately reviewed materializer. That parser must verify the PAX commit comment, fixed prefix, all 2,445 member paths, modes, sizes and Git blob SHA-1 values before writing the owner-only source tree. The materializer's exact post-write verifier remains mandatory. Acquisition alone does not claim that archive contents were parsed safely.

Only after both source stages pass may the root-owned workflow run unchanged `npm ci` from lock `56cbf67c...`, the SDK 2.116 request-shape unit, and unchanged `npm run build` on the materialized source. Those commands require their separately reviewed long-process custody and complete pre/post source parity. This helper does not install packages, contact npm, compile the App, open a browser, manufacture authentication, answer provider requests or activate an economic route.

The local tests are support and negative controls. They prove manifest closure, literal command construction, private fresh parents, held-FD/path replacement refusal, source-root replacement refusal, wrong HEAD refusal, timeout/input refusal and frozen-helper byte admission. They deliberately never manufacture a complete archive and cannot establish the Linux primary positive. A real Linux CI run with the exact checkout, genuine Git archive, no skipped custody controls, materializer PASS and no surviving owned process is required before this source-acquisition gate can be marked integrated-runtime-tested.
