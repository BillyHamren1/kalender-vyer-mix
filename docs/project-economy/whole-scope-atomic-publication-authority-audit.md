# Whole-scope atomic publication authority audit

Status: design audit only, 2026-10-02. Source baseline: Operations `b4272d1d` as identified by the parent; citations below point to inspected local source paths. This document adds no writer, permission, consumer or calculation. The existing [Finance copy proposal](whole-scope-cost-publication-finance-copy-v1-proposal.md) remains a proposal, not a locked API.

The missing bridge is an Operations-owned transaction that derives, validates and saves the invoice-only projection from actual persisted authority, then saves its immutable destination outbox. Current SQL captures evidence; current TypeScript calculates after that SQL transaction ends. A prior HTTP read, client hash, service identity or supplied calculated amount cannot authorize a new durable publication. Finance must copy a saved Operations result and cannot repair this gap by calculating components.

## Proposed persisted bridge

Prefer a NEW narrow private database calculator/validator and publication entrypoint, default off. No caller money, status, actor, calculated JSON or arbitrary SQL is accepted. A request selects a real enrolled canonical scope and expected immutable scope/composition/publication tokens, plus a bounded idempotency key and reason. Authorization derives the actor and organization or uses an explicit server-maintained publication enrollment with equally concrete current scope/member permissions. A service credential alone is insufficient authority.

The transaction obtains the reviewed whole evidence using the actual private reader, calculates the restricted invoice projection inside the same transaction, validates exact source/projection parity, and commits the immutable evidence, result, publication head and all destination outbox records together. Failure leaves all four unchanged. A trusted candidate produced in a previous transaction is still only a candidate: final commit must independently reconstruct and check the locked inputs and result. Hash comparison against caller-selected data is not that check.

A SQL implementation is a new Operations calculator with a restricted adapter, not a Finance calculator. It requires independently reviewed differential vectors against the unchanged TypeScript kernel and adapters. Merely moving the outer aggregation to SQL leaves kernel validation incomplete. Preserve per-obligation replacement and consumption validation, duplicate/tenant/currency checks, safe-integer bounds and all rejected/unresolved paths. No dynamic SQL from a request and no unrestricted execution of TypeScript inside PostgreSQL is proposed.

Save the full private source evidence, deterministic calculation version and projection; publish only the approved redacted destination manifest. Semantic evidence/publication fingerprints must use specified purpose-prefixed canonical bytes and shared SQL/TS vectors, not `jsonb::text`. Observation time is fixed on first commit, not refreshed by replay. The exact wire-byte hash remains independent. Idempotency returns the saved original receipt without advancing the head; changed command under the same key fails. Deliberate stale business CAS uses bounded nonretryable conflict behavior, not a permanent `40001` retry loop.

## Lock composition that still needs approval

A new publisher must not call the existing reader first and acquire scope reservation locks afterward. Propose a single reviewed order: actual actor/admin and deterministically ordered live member authorization; publication/enrollment gates SHARE; `obligation-org:<org>`; `operations-economic-scope:<org>`; the entire globally sorted invoice barrier set; scope/composition/baseline/source/policy head locks and exact currentness rechecks; publication head UPDATE; immutable rows and outbox inserts. There must be no earlier leaf or individual invoice lock before the complete invoice selector set.

This is a proposed combined order, not an established property of current writers. Scope enrollment takes only the reservation barrier; composition/baseline/policy take only the obligation barrier; receivers take only invoice barriers. The source audit finds no existing reservation→obligation call in the cited paths, but native reverse-order tests must verify the combined order and project/auth lock interactions before implementation is accepted. Preflight discovery cannot freeze missing members: repeat discovery under the selected barriers and reject drift, with bounded retry if acquiring an enlarged ordered lock set would invert order.

`scope_membership_v1` reconstructs relationships and locks the actual root/packing policy ([scope helper](../../supabase/migrations/20261002014937_operations_project_scope_enrollment.sql#L73), lines 73–167). Neither a root SHARE lock nor the reservation key proves that every legacy relationship INSERT/UPDATE/DELETE participates. The first publication must therefore retain `as_of_graph`. A stronger claim that graph membership cannot change before commit requires a separately audited writer protocol covering new/absent relationship rows and project joins. Do not add that stronger claim from a final SELECT alone. Likewise saved receiver source heads cannot prove upstream completeness or absence of unpublished provider changes.

## Exact parity and currentness requirements

| Field or condition | Required persisted meaning |
| --- | --- |
| Resolved positive invoice | Actual permanent binding, current baseline, same local obligation/project/currency, saved V1 proof and unified V1/V2 economic revision/fingerprint agree. Equal V2 enrichment does not add a second charge. Higher/conflicting economics makes the old binding unresolved. |
| Current policy | Actual immutable policy event/revision/fingerprint; replacement/consumption copied only when current. Missing/stale policy preserves diagnostic and NULL policy money; a known invoice amount can remain known without promoting EAC. |
| Excluded source | Permanent anchor/history retained; unresolved, rejected, withdrawn or unsupported source contributes no current amount. Rejection does not erase the baseline obligation. |
| Inventory | Preserve all actual anchors and the full current 18-field inventory plus historical 13-field references. Whole validator forbids duplicate anchors across members and checks outer/leaf proof agreement ([validator](../../supabase/functions/_shared/project-scope-invoice-kernel-evidence.ts#L73), lines 73–98). `captured_inventory_matches_current=false` is an explicit historical/current diagnostic, not permission to reuse old money. |
| Partial totals | Sum only actual resolved child confirmed/preliminary results. All three copied partial amounts are NULL when resolved count is zero. A status subtotal can be zero when other resolved sources exist. No hidden zero for an unknown source and no unsupported-currency conversion. |
| Unknown scope coverage | Personnel/supplier/catering/other coverage and source coverage remain unavailable; credit eligible false; remaining/EAC/budget/margin NULL. Manual known estimate/commitment composition values are not a Booking revenue budget or whole forecast. |
| Historical read/replay | Original saved bytes and source fingerprints remain immutable. New corrections create a higher publication and explicit destination withdrawals. A current read checks saved/current scope, composition and source proofs; it does not rewrite history. |
| Alias | Metadata view only. No preview, subset or alias hash authorizes a whole-scope publication, destination grant or financial total. Canonical stream identity remains independent. |

## Native acceptance gates before building or enabling transport

1. Differential SQL/TypeScript vectors cover no sources; excluded-only; confirmed/preliminary combinations; missing/stale policy; NULL baseline; over-replacement/consumption; duplicate anchor; unsafe integer total; Unicode/canonical JSON and full evidence hashes. Every exact projection field, diagnostic and NULL must match.
2. Real two-session publisher versus scope enrollment/composition/baseline/policy writers in both lock orders. Observe actual `pg_stat_activity` Lock waits. After advancement, stale expected tokens fail with no publication/outbox mutation; prior immutable receipts remain readable.
3. Actual V1 and V2 receiver advance, first absent counterpart insertion, equal enrichment, conflicting equal economic proof and higher economics versus publisher. There is one economic charge, or explicit unresolved evidence; no mixed-time source set.
4. Actual admin/profile/project/gate revoke in both orders, including a removed/new member. Revoke before acquisition denies; revoke waiting behind held SHARE locks affects the next request. No invented instant revocation-after-commit guarantee. Audit bypass paths and default privileges; service cannot write result/head/receipt tables directly.
5. Simultaneous identical and conflicting CAS/idempotency calls: one saved version, deterministic replay, no duplicated outbox. Saved head can advance only to its actual matching immutable publication; identity rewind/delete/truncate denied.
6. Destination mapping/whole-target authorization and route/key revocation are separately locked and checked. All historical recipients receive explicit withdrawal after remapping. Lost HTTP response after receiver commit retries identical bytes with a fresh nonce and resolves to one saved Finance copy/strict receipt. No Finance component re-addition.
7. Logs retain only bounded typed redacted proof IDs/hashes/versions and closed phase/SQLSTATE diagnostics. Use a fresh named disposable database, strict environment/path guards and bounded owned-child cleanup. No customer/provider/hosted operations.

These gates are new work, not covered by the accepted hired-authority concurrency or existing read-only HTTP tests. The next safe implementation decision is the restricted Operations database calculator/parity contract and combined barrier review. Whole cost/EAC coverage and Finance target authority remain separate open prerequisites.
