# Hosted baseline metadata query

This adjunct is one SELECT statement for a separately verified Operations hosted baseline. Root must first verify the established Lovable project, database status and source/environment linkage. The known expected baseline is PostgreSQL 15.8, UTF8, with anon/authenticated/service roles and no new economy/invoice/product private namespaces or first-two/product public APIs. Database name or metadata shape cannot establish the correct project. The query itself neither requests account access nor authorizes its execution; only root performs an authorized connector read.

The query owns only `scripts/project-economy/operations-compatible-catalog-hosted-baseline-read.sql` and this contract. Both stay outside the frozen 93-file disposable collector, its exact 23 DDL, existing source manifests and product migrations. There is no SET, transaction command, DDL, write, application-table access, monetary calculation, application-function invocation or dispatch. All named introspection/hash/ACL functions are pg_catalog builtins; COALESCE is SQL syntax. No source definition, configuration value, account/customer data, JWT/service key or connection string is returned.

Twelve explicit schema/function-name targets cover auth.uid, two known existing organization/role helpers and the absent candidate entries; all overloads and explicit zero-count absences are returned. Six explicit namespace targets report presence, owner/ACL hash, PUBLIC grantee-0 USAGE/CREATE and effective anon/authenticated/service USAGE. Routines report identity arguments, result/language/kind, owner, security-definer and exactly-one-empty-path flags, source/config/ACL hashes, extension membership and PUBLIC/effective client EXECUTE. Additional non-path function configuration remains private while influencing its hash. Absence and overloads are never resolved by selecting a first row.

The result always labels baseline_only=true, full_certificate=false, candidate_admission=false and external_project_identity_required=true. Wrong version/encoding, missing expected role, any candidate namespace or public candidate API produces a closed unavailable result. More than 64 selected routines or 128KiB serialized metadata also produces unavailable; no list is truncated into a positive result. The parent applies its connector deadline and response-integrity checks; this single SELECT cannot set a server timeout. It makes no claim that the surrounding transaction is READ ONLY or REPEATABLE READ.

A successful result is a named baseline metadata observation only. Other functions/namespaces, full inherited role graph, arbitrary/dynamic dispatch, generated/extension provenance, candidate installation and native release remain explicitly unresolved. It cannot substitute for AA8's first-two native proof, the new disposable selected-catalog job, or the whole candidate/hosted activation audit. Supplemental isolated guard/privacy/cap tests do not imply a hosted query was executed.
